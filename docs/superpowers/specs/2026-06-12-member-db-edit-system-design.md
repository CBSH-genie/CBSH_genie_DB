# 인명사전 읽기+수정 시스템 설계

- 날짜: 2026-06-12
- 작성: 안연수 + Claude
- 배경: 기장 톡방(2025-11-20 ~ 2026-01-25) 논의 반영

## 목표

현재 읽기 전용인 충북과학고 공학동아리 인명사전 웹사이트에 **본인 정보 직접 수정** 기능을 추가한다.
구글 시트를 단일 원천(SSOT)으로 유지하고, 서버 비용 0원, 인수인계 부담 최소화를 지킨다.

## 범위

- 포함: 멤버 목록 읽기(즉시 반영), 본인 PIN 인증 후 정보 수정, 역대 소속·최종수정일 표시
- 제외(다음 단계 후보): 홈커밍 행사 페이지, 회계 현황, 신규 등록 웹 입력(기존 구글 폼 유지), 프로필 사진

## 기장 톡방에서 확정된 요구사항

1. 시트가 메인 뼈대, 웹은 빠른 검색용 (절충안)
2. 개인이 직접 수정 + 최종 수정일시 명시
3. 진로(역대 소속)는 필수에 준하는 핵심 항목
4. 유지보수에 숙련도가 필요 없을 것, 매뉴얼 작성, 인수인계 쉬울 것
5. 기존 자산 활용: CBSHgenie2020 구글 계정, Genie-official 깃헙

## 아키텍처

```
[부원 브라우저]
   GitHub Pages (index.html + config.js)  ← 기존 구조 유지
        │  읽기: GET  → 멤버 목록 JSON (PIN 제외, 즉시 반영)
        │  쓰기: POST → {식별자, PIN, 변경 필드}
        ▼
   Apps Script 웹앱 (Master 시트에 바인딩, CBSHgenie2020 계정으로 배포)
        │  PIN 검증 → 해당 행만 수정 → 최종수정일 자동 기록
        ▼
   구글 시트 Master (SSOT — 기장단은 시트 직접 편집 가능)
```

- 기존 "웹 게시 CSV" 경로는 제거하고 Apps Script 단일 경로로 통일한다.
  - 효과: "웹 게시가 풀렸어요" 문제 소멸, 수정 후 5분 지연 없이 즉시 반영.
- Apps Script 코드는 저장소 `apps-script/Code.gs`로 버전 관리한다. 배포는 시트의
  확장 프로그램 → Apps Script 편집기에 복사-붙여넣기 후 웹앱 배포.
- `config.js`는 `SHEET_CSV_URL` 대신 `API_URL`(Apps Script 배포 URL)을 갖는다.
  `SURVEY_URL`(신규 등록 폼)은 유지.

## 데이터 모델 (Master 시트 열)

| 열 | 이름 | 기수 | 역할 | 현재 소속 | 역대 소속 | 전화 | 이메일 | 관심사 | PIN | 최종수정일 |
|----|------|------|------|-----------|-----------|------|--------|--------|-----|------------|
| 신규 | | | | | ✅ | | | | ✅ | ✅ |
| 웹 노출 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ |
| 본인 수정 가능 | ❌ | ❌ | ❌ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 자동 |

- 행 식별: 이름 + 기수 조합 (동명이인은 기수로 구분; 같은 기수 동명이인 발생 시 기장이 시트에서 구분자 추가)
- PIN 초기값: 전화번호 뒤 4자리 (기장이 일괄 세팅, 전화번호 없으면 기장이 임의 발급 후 개인 전달)
- PIN은 본인이 수정 화면에서 변경 가능
- 읽기 API는 내보낼 열을 화이트리스트로 관리한다 (PIN은 어떤 응답에도 포함 금지)
- 최종수정일: 쓰기 성공 시 서버(Apps Script)가 자동 기록. 시트에서 기장이 직접 고친 행은 기장이 수동 갱신(매뉴얼에 명시)

## 컴포넌트

### 1. `apps-script/Code.gs` (신규)

- `doGet()`: Master 시트 전체를 JSON 배열로 반환. 화이트리스트 열만 포함.
- `doPost(e)`: JSON body `{name, cohort, pin, fields: {...}}`
  - 이름+기수로 행 탐색 → 없으면 `{ok:false, error:"not_found"}`
  - PIN 불일치 → `{ok:false, error:"wrong_pin"}`
  - `fields`가 비어 있으면 PIN 검증만 수행하고 `{ok:true, member: {...}}` 반환 (모달 1단계용, 시트 수정 없음)
  - 수정 가능 열 화이트리스트 검증 후 해당 셀만 갱신, 최종수정일 기록
  - 성공 → `{ok:true, member: {...갱신된 행...}}`
- CORS: 웹앱을 "모든 사용자" 액세스로 배포, POST body는 `text/plain`으로 전송해 preflight 회피 (Apps Script 표준 패턴)

### 2. `index.html` (수정)

- 읽기: `fetch(API_URL)` → JSON 파싱 (기존 CSV 파싱 로직 대체). localStorage 캐시 로직은 유지.
- 카드 UI:
  - 역대 소속: 현재 소속 아래 작은 텍스트로 표시
  - 최종수정일: 카드 하단에 작게 표시 (오래된 프로필 식별용)
  - "수정" 버튼 추가
- 수정 모달:
  1. PIN 입력 단계 → POST로 검증(필드 없이 PIN만 보내 확인)
  2. 성공 시 수정 폼 (현재 소속, 역대 소속, 전화, 이메일, 관심사, 새 PIN[선택])
  3. 저장 → 성공 토스트 + 해당 카드 즉시 갱신 + localStorage 갱신

### 3. `config.js` (수정)

```js
const API_URL = "https://script.google.com/macros/s/.../exec";
const SURVEY_URL = "https://forms.gle/...";  // 신규 등록용, 유지
```

### 4. `readme.md` (전면 갱신)

- 운영 원리 3줄 요약 갱신 (CSV 게시 → Apps Script)
- 연차 루틴: 신입 추가(폼 → Master 붙여넣기 → PIN 일괄 세팅)
- Apps Script 재배포 절차 (단계별, 비개발자 기준)
- 문제 해결 FAQ (배포 URL 바뀜, PIN 분실, 데이터 안 뜸)

## 에러 처리

- PIN 불일치: 에러 토스트. 잠금/횟수 제한 없음 (전화 뒷자리 수준 민감도, 과설계 회피)
- API 읽기 실패: localStorage 캐시로 표시 유지 + 안내 토스트
- API 쓰기 실패(네트워크 등): 에러 토스트, 입력값은 모달에 유지 (재시도 가능)
- 동시 수정: 행 단위 마지막 저장 우선 (구성원 규모상 충돌 가능성 무시 가능)

## 테스트

- Apps Script: 사본 시트에 배포해 curl로 검증
  - 읽기: 전체 목록 반환, PIN 열 미포함 확인
  - 쓰기: 정상 수정 / 잘못된 PIN / 없는 멤버 / 수정 불가 열 시도 각 케이스
- 프런트: 로컬 서버(`python3 -m http.server`)에서 테스트 배포 URL 연결, 검색·수정·캐시 동작 확인
- 마이그레이션 확인: 실제 Master 시트에 신규 열 추가 후 기존 데이터 표시 정상 여부

## 마이그레이션 순서 (배포 시)

1. Master 시트에 역대 소속·PIN·최종수정일 열 추가, PIN 일괄 세팅
2. Apps Script 코드 부착 + 웹앱 배포 → URL 확보
3. `config.js`에 API_URL 반영, `index.html` 새 버전과 함께 푸시
4. 동작 확인 후 기존 "웹에 게시"(CSV) 중지, Web 시트 정리
